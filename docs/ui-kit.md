# ui_kit developer notes

`packages/ui_kit` holds shared widgets. It depends only on Flutter, `signals_flutter` (exact pin) and `theme_core`, so widgets are tested with plain data.

- **Theme:** `ThemeController` (signals) holds the player's `AppearanceSetting` and the resolved theme. `ThemeController.load(rootBundle)` reads the three built-in themes from `theme_core`'s assets (`loadBuiltInThemes`); the app passes `controller.themeData` to `MaterialApp`. System follows `controller.osBrightness`, which the app keeps current from the platform. The controller never stores anything: it calls `onChanged` and the app's repository saves. `buildBardThemeData` maps a `ResolvedTheme` to `ThemeData` and attaches `BardTokens`, so widgets use `BardTokens.of(context).window`, `.ink`, `.chip(ChipKind.success)` and never a colour literal. `AppearanceSelector` (and `showAppearanceDialog`) is the theme and variant drop-down with Reset to System. Tests use `test/support.dart` (`testTheme`, `testResolver`), which reads the built-in JSON from `../theme_core/assets/themes/`.
- **Window widgets:** `ShellWindow(title:, child:, expand:, accent:)` is the framed window every panel uses; `ResultChip(kind:, label:)` always shows glyph and word, with a 2 px outline in the high-contrast variant; `RecordCard` draws label/value tables on `labelCell` and takes every word from the app. `PerspectivePanel` is a `ShellWindow` with a kind chip.
- **Not built:** the theme editor, custom themes, import and export, document mode and the Handler-forced effect tokens' widgets. The design is in [architecture/07-apps.md](architecture/07-apps.md#themes-and-player-appearance-settings).
- **Dice breakdown:** `DiceBreakdownView(data: DiceBreakdownData(...))`. The app maps the engine's `CheckResolved` into this data. Every number, including group subtotals, comes from the engine; the widget does no arithmetic.
- **Perspective panel:** `PerspectivePanel<T>` shows a `ReadonlySignal<List<T>>` already filtered for one perspective. Give it a bounded height.
- **Phone panel:** `PhonePanel(threads: ..., onSend: ...)` shows `PhoneThreadData` (id, title, messages) for one viewer and calls `onSend(threadId, text)`; the app turns that into `SendPhoneMessage` and maps `phoneConversations(...)` from the engine into the data. The cap counts UTF-16 units (2,000, as the engine and relay rules); `sendDisabledReason` replaces the compose box, for accounts that may not message. The console and dossier views in `apps/bard` host it (`apps/bard/lib/ui/console/console_view.dart`, `apps/bard/lib/ui/dossier/dossier_view.dart`).
- **Phone panel limits:** `PhonePanel.maxLength` defaults to the literal 2000 and the invisible-character list is a copy, because ui_kit does not import the engine. Both mirror `maxPhoneTextUnits` and `invisiblePhoneChars` in `packages/engine/lib/src/phone.dart`; change them together.
- **Tests:** `cd packages/ui_kit && flutter test`.
