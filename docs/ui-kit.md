# ui_kit developer notes

`packages/ui_kit` holds shared widgets. It depends only on Flutter and `signals_flutter` (exact pin), so widgets are tested with plain data.

- **Theme:** `BardTheme.light()` / `dark()` is a placeholder. The dossier look is not implemented yet and waits on D's feedback on the UI style (open: [UI style review](architecture/09-open-decisions.md#ui-style)); replace `theme.dart` only.
- **Planned theme model (not built):** Per-player themes are planned: three built-in themes plus a System option that follows the OS brightness, each theme with up to four variants (normal, high contrast, red-green safe, blue-yellow safe), custom themes with no theming limits, derived themes that name a base and store only overrides, window edge, effect and document colour tokens, a document mode with a fixed standard paper set, and import and export. The design is in [architecture/07-apps.md](architecture/07-apps.md#themes-and-player-appearance-settings). Boundaries: the theme model lives in a separate pure-Dart package (Proposed name `theme_core`, open: [T11](architecture/09-open-decisions.md#t11)): documents, codec and validator, token registry, resolver (fallback built-in, base chain, cycle and depth checks, missing-token fill, effect-safety pairs), colour math, the standard paper set and the built-in themes as JSON assets. `ui_kit` keeps the asset loader for the built-ins, the settings, selector, editor and document-mode widgets, and a `ThemeController` mapping resolved tokens to `ThemeData` (Proposed, open: [S-4](architecture/09-open-decisions.md#s-4-how-the-built-in-theme-json-ships)). Storage is the apps' `AppearanceRepository` over the local store only (client-side); `ui_kit` never touches storage, Firebase or the session. Handler-forced effects reach `ui_kit` only as token names from their own features. Until it is built, `BardTheme` stays the placeholder.
- **Dice breakdown:** `DiceBreakdownView(data: DiceBreakdownData(...))`. The app maps the engine's `CheckResolved` into this data. Every number, including group subtotals, comes from the engine; the widget does no arithmetic.
- **Perspective panel:** `PerspectivePanel<T>` shows a `ReadonlySignal<List<T>>` already filtered for one perspective. Give it a bounded height.
- **Phone panel:** `PhonePanel(threads: ..., onSend: ...)` shows `PhoneThreadData` (id, title, messages) for one viewer and calls `onSend(threadId, text)`; the app turns that into `SendPhoneMessage` and maps `phoneConversations(...)` from the engine into the data. The cap counts UTF-16 units (2,000, as the engine and relay rules); `sendDisabledReason` replaces the compose box, for accounts that may not message. The console and dossier views in `apps/bard` host it (`apps/bard/lib/ui/console/console_view.dart`, `apps/bard/lib/ui/dossier/dossier_view.dart`).
- **Phone panel limits:** `PhonePanel.maxLength` defaults to the literal 2000 and the invisible-character list is a copy, because ui_kit does not import the engine. Both mirror `maxPhoneTextUnits` and `invisiblePhoneChars` in `packages/engine/lib/src/phone.dart`; change them together.
- **Tests:** `cd packages/ui_kit && flutter test`.
